# Adding a study

Each study is a top-level directory, self-contained and reproducible on its own. This
is the convention [`Trump-Youngstown/`](../Trump-Youngstown/) establishes; follow it so
that a reader who knows one study can navigate any of them.

## Naming

`Subject-Anchor` in title case — the thing being examined and what it is examined
against. `Trump-Youngstown` is the 2024 immunity decision read against Jackson's 1952
concurrence. Keep it short enough to type.

## Layout

```
<Study-Name>/
  README.md           the paper itself, written for GitHub
  Makefile            every step, in order
  requirements.txt    pinned to what the analysis was actually run with
  .gitignore          derived data, models, caches
  docs/
    METHOD.md         the formal model and the full statistics
    PROVENANCE.md     what was tried, in order, including what failed
  paper/              the manuscript as submitted; hand-made figures
  src/                analysis code, flat unless it grows past ~30 files
  data/raw*/          primary sources, committed
  data/proc/          derived, git-ignored, rebuilt by `make all`
  out/                generated figures (PNG + PDF) and write-ups
  scripts/            fetchers for anything too large to commit
```

## The four documents

**`README.md` — the argument.** This is the paper, rendered for GitHub: a title, the
question, the method in plain language, the figures inline, the result, the cautions,
and the answer. Open with a one-paragraph statement of the question and a small table
of headline numbers, so a reader who stops after ten seconds still leaves with the
finding. Close with a short index of everything else in the directory.

**`docs/METHOD.md` — the check.** Equations, the full statistics table, every
robustness test and its outcome, the null results, the judgment calls, and the known
data issues. Written for someone trying to break the result. State what *would* have
broken it and what happened when that was tried.

**`docs/PROVENANCE.md` — the route.** What was attempted in order and why each failure
forced the next step. The final design is rarely the first; this is where the earlier
ones are recorded. It doubles as the source for a methods section.

**`paper/`** — the manuscript in whatever format it was written, plus any figure not
produced by code. Code-generated figures belong in `out/`.

## Rules that make a study reproducible

1. **`make all` rebuilds every number from raw text.** If a figure or statistic in the
   README cannot be regenerated by a Makefile target, it does not go in the README.
2. **Commit primary sources, ignore derived ones.** Raw opinions are small and stable;
   embeddings and caches are large and regenerable. Anything in `data/proc/` must be
   reconstructible.
3. **Pin dependencies** in `requirements.txt` to the versions the published numbers
   were produced with.
4. **Large binaries are fetched, not committed** — put the fetcher in `scripts/` and
   the target path in `.gitignore`.
5. **One file per judgment call.** Any place a human decision enters the analysis —
   a hand-drawn partition, a set of labels, a domain assignment — lives in exactly one
   file, is named in the README, and can be edited by a reader who disagrees.
6. **Report the null results.** They are what justify the design that worked.
7. **Permutation and bootstrap, not asymptotics.** Where a result rests on a hand-made
   choice, include a placebo test that substitutes a random choice of the same shape.

## Wiring it up

After the study directory exists:

1. Add a row to the **Studies** table in the [root README](../README.md) — study,
   question, finding, status.
2. Confirm the study's own `.gitignore` covers `data/proc/`, models, and caches, and
   that `git status` is clean after a full `make all`.
3. Check the study README renders on GitHub: relative image paths, tables, and the
   links to `docs/METHOD.md` and `docs/PROVENANCE.md`.
